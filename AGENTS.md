## What you may do

Read anything. Clone anything. Build on anything, under each repository's own licence.
Open issues and pull requests. Take a work package from a repository's roadmap or packet
surface and finish it: a package is done when its stated acceptance command exits 0.

## What you may not do

Push to a default branch. Mint a DOI. Edit `attest/`. Those are the author's acts, taken
under a typed gate on his own machine, and no agent performs them.

## How to be useful here

1. Retrieve before asserting. The live state is in the repository, not in your memory of it.
2. Where a value is unknown, write `not established`. An invented limit is worse than an
   absent one.
3. A performance, coverage or completeness claim needs a recorded measurement in the same
   change. Otherwise delete the claim, not the measurement.
4. One package, one pull request, one proof. Do not batch.
5. Report a refusal. Do not route around it.
6. Work is labelled by capability — `needs:code`, `needs:proof`, `needs:testing`,
   `needs:ontology`, `needs:visual`, `needs:legal`, `needs:human` — never by model name.
   Which agent takes a package is a human dispatch decision, not a property of the work.
